# 추천 성과 회고

**언제 읽나**: 매주 월요일 brief(7일 회고) / 매월 1일 brief(30일 회고) / 사용자 "회고" 요청 시.
**역할**: 과거 추천이 실제로 어떻게 됐는지 측정해서 AI 의 reasoning 을 학습 루프에 넣는다.
정량 데이터(수익률·벤치마크 대비) + 정성 narrative(왜 맞았나·왜 틀렸나). 정해진 임계값·카테고리 없음 — AI 가 직접 분석.

---

## 데이터 수집 절차

### 1. 과거 추천 추출

```
notifier_mcp.list_recent_dashboards(limit=30)
```

각 대시보드에서 다음을 파싱:
- 추천 종목 (매수/매도/보류)
- 추천 날짜
- 추천 시 가격 (시세 앵커 기록값)
- 추천 시 narrative (강점·약점·hidden risk 등 추천 근거)

### 2. 현재가 + 변동률 계산

```
portfolio_mcp.get_portfolio_data()
```

- 보유 종목 → 응답의 `current_price` 사용
- 보유하지 않는 후보 종목 → 웹 검색으로 현재가 확인 (`"{종목} stock price"`)

각 추천 종목에 대해:
- **수익률** = (현재가 − 추천 시 가격) / 추천 시 가격 × 100
- **벤치마크 대비** = 수익률 − 같은 기간 S&P500(미국) 또는 KOSPI(한국) 변동률

### 3. 실현 손익 (실제 매매한 경우)

```
portfolio_mcp.get_realized_pnl()
portfolio_mcp.get_trading_history(period_days=30)
```

추천대로 매매했는지 + 결과 손익 확인.

## 7일 회고 (매주 월요일)

지난 7거래일 동안의 추천을 평가.

### 출력 가이드

```
📊 주간 추천 회고 (YYYY-MM-DD ~ YYYY-MM-DD)

추천 건수: 매수 X / 매도 Y / 보류 Z
적중률: A/B (양의 수익률 비율)
평균 수익률: +/-x.x% (벤치마크 대비 +/-x.x%p)

🟢 잘 된 추천:
[종목별 narrative — 추천일 → 현재 수익률, 벤치마크 대비, 적중 원인]

🔴 실패한 추천:
[종목별 narrative — 추천일 → 현재 수익률, 벤치마크 대비, 실패 원인]
[AI 가 실패 원인을 자유 분류 — 거시·리스크·이벤트·타이밍·펀더 변화·시장 심리 등 다양한 가능성]

📌 이번 주 학습:
[반복 패턴 또는 통찰을 narrative 로 1~2줄]
```

실패·성공 기준은 AI 가 절대 수익률 + 벤치마크 대비 + 추천 의도 보고 종합 판단 (정해진 -5%/-3%p 같은 임계값 없음). 단일 -2% 도 의미 있는 실패일 수 있고 -8% 도 macro 충격으로 양해 가능할 수 있음.

```
📊 월간 추천 회고 (YYYY-MM-DD ~ YYYY-MM-DD)

[7일 회고 형식과 동일]

🎯 실패 원인 분석:
[AI 가 실패 사례들을 보면서 반복 패턴·공통 원인을 찾아서 narrative]

💡 다음 달 개선:
[AI 가 도출한 통찰 narrative — 어떻게 다르게 reasoning 할지]
```

## 회고 후 개선 제안 (PR 모드)

회고에서 *반복 패턴* 이 발견되면 AI 가 직접 PR 을 생성한다. 자동 merge X — 사용자 review 가 최종 gate.

### PR 생성 조건

- 동일 카테고리/원인의 실패가 **3건 이상 누적** 됐을 때 (단발 사례는 회고 narrative 에만 적고 PR 안 만듦)
- 변경이 *추가·보강* 성격일 때 (예: 새 사실 추가, 컨텍스트 보강)
- 변경 위치가 **수정 가능 영역** 내일 때 (아래 참조)

조건 미충족이면 회고 섹션의 narrative 에만 패턴 보고. PR 없음.

### 수정 가능 영역

✅ **PR 자동 생성 가능:**
- `SKILL.md` (스킬 본문)
- `references/buying-framework.md` (한국 세금·사용자 컨텍스트)
- `references/crisis-playbook.md` (위기 톤·관점)
- `references/dashboard-design.md` (출력 형식)
- `references/retro.md` (이 파일 자체 — 회고 방식 개선 가능)

❌ **수정 금지 (AI 안전망 — 사용자 명시적 요청 시만 수정):**
- `.claude/hooks/*` (Stop hook 검증 코드 — AI 가 자기 검증을 약화시키는 것 방지)
- `.claude/settings.json` (hook 등록 설정 — Stop hook 우회 방지)

위 두 영역은 회고에서 "Stop hook 가 너무 엄격하다·검증 룰 추가하고 싶다" 같은 판단이 들어도 PR 만들지 않음. 사용자가 직접 요청한 경우에만 수정.

### PR 생성 절차

1. **새 브랜치** 생성: `retro/YYYY-MM-DD-<주제 슬러그>` (예: `retro/2026-05-20-strengthen-hidden-risk`)
2. **수정 사유** 명시한 커밋 (커밋 메시지에 회고 기간·근거 한 줄)
3. `gh pr create` 로 PR 열기
4. **PR description 필수 포함:**
   - 회고 기간 (YYYY-MM-DD ~ YYYY-MM-DD)
   - 실패 사례 수 + narrative
   - 제안 변경의 근거 — 왜 이 수정이 AI 의 더 나은 reasoning 을 돕는가
   - 예상 효과 — 변경 후 다음 회고에서 어떤 개선이 보일 것 같은지
   - **자체 점검**: 이 PR 이 AI 자율 판단 원칙을 약화시키지 않음 (처방·임계값·강제 룰 추가가 아님)

### Sweep PR 원칙

매 회고마다 PR 만들지 않음. *정말 패턴이 보일 때만*. 별 패턴 없으면 회고 narrative 에 "이번 주는 특이 패턴 없음" 한 줄로 끝. AI 가 패턴 있는지 자체 판단 — 조건 안 맞으면 PR 안 만듦.

### 사용자의 역할

- PR 받으면 GitHub 에서 review
- merge 하면 다음 brief 부터 변경 적용
- close 하면 무시 (회고 narrative 는 기록으로 남음)
- PR 댓글로 "조금 더 보수적으로" 같은 피드백 가능 — AI 가 다음 회고에서 재작업
